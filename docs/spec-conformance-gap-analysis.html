총평 & 점수

골격(데이터 모델, 8 Phase의 테이블/엔드포인트/UI 스캐폴딩)은 기획안을 충실히 따라 "넓게" 구현되어 있습니다. 그러나 기획안의 지능·자동화 핵심 3축 — ① LangGraph가 라이프사이클을 실제로 구동, ② Navigator가 LLM(LangChain)으로 판단, ③ rate-limit/메모리 자기진화가 폐루프로 동작 — 이 규칙/스텁/수동으로 대체되어 있어, 부 목적(LangChain·RAG·LangGraph 실전 포트폴리오)이 실질적으로 충족되지 않습니다. 즉 "형태는 맞고 두뇌가 비어 있는" 상태.

CRITICAL  1. LangGraph가 실제 라이프사이클 런타임이 아니다

D2 · §3 핵심 멘탈모델 · §5 · 목표프롬프트 "우회 금지"
기획"LangGraph StateGraph가 라이프사이클 런타임(LLM 아님)" — intake→navigate→dispatch→watch→review→complete→ingest의 단일 런타임. checkpointer로 durable.
구현실제 구동은 폴링 컨테이너 2개: worker_loop(3s)+watcher_loop(2s). LangGraph orchestrator.run_ticket은 수동 엔드포인트 POST /tickets/{id}/orchestrate로만 호출 — 헤드라인 "드래그=실행" 경로는 LangGraph를 전혀 거치지 않음.
갭오케스트레이션의 단일 진실 런타임이 LangGraph가 아니라 두 폴링 루프. 그래프는 부차적 데모 경로. 그래프 노드도 review/complete/ingest-memory/subdivide 누락(navigate→dispatch→watch만).
증거infra/docker-compose.yml(worker/watcher 서비스) · orchestrator.run_ticket 호출처 = tickets.py:161 단 한 곳 · orchestrator.py 노드셋

CRITICAL  2. Navigator가 LLM/LangChain이 아니라 키워드 규칙기반

D2 · D5 · §6 · §17 · 목표프롬프트 "LangChain·RAG 의도적 사용, 우회 금지"
기획"Navigator = LangChain chain(RAG 주입→CLI LLM→구조화 파서→navigator_decisions)". 부 목적(AX 포트폴리오)의 핵심.
구현navigator.recommend()은 순수 파이썬 키워드 카운트 스코어링(PERSONA_KEYWORDS). LLM 호출·LangChain 체인 없음. langchain-core가 requirements에 있으나 코드에서 한 번도 import 안 됨.
갭아키텍처 다이어그램의 "Navigator(LLM)"이 실제로는 "Navigator(rules)". 의도적 LangChain 채택이 0. RAG도 결정에 키워드-해시로만 주입(아래 #8).
증거navigator.py 전체(키워드 dict + _score_personas) · grep "from langchain" → 0건

CRITICAL  3. LangGraph checkpointer가 Postgres가 아닌 MemorySaver

D15 · §3 · §15(복구) · §5
기획"checkpointer = Postgres" → 정전/재시작에도 "워크플로우는 마지막 체크포인트부터 이어짐"(§15).
구현g.compile(checkpointer=MemorySaver()) — 인메모리. 프로세스 죽으면 그래프 상태 소멸. 주석도 "MVP/tests, Postgres가 production target"으로 인정.
갭그래프 레벨 durable 재개 불가 → §15의 "checkpointer로 이어짐" 보장 미충족. (run 레벨 재큐는 durability가 따로 처리하나, LangGraph 상태는 아님.)
증거orchestrator.py:24,148

MAJOR  4. Rate-limit 자동 재개가 폐루프로 닫히지 않음

D10 · D21 · §14 · §23 성공기준
기획감지(SSOT 패턴)→스냅샷→Haiku가 리셋시각 파싱→scheduled_jobs cron→UI에 티켓#·재시작시각→리셋 후 자동 resume(CLI --resume 또는 신규 re-dispatch).
구현감지/분류 O, schedule_rate_limit_resume가 durable job 생성 O. 그러나 — (a) Haiku 파싱 미구현: _handle_rate_limit은 주석만, 실제로는 +5h 고정. (b) scheduled_jobs(fire_at)를 발화시켜 resume하는 코드가 어디에도 없음(scheduler_loop은 ingest/audit/snapshot만). (c) POST /runs/{id}/resume 엔드포인트(§21) 부재. (d) 프론트에 rate-limit 표시 0(grep rate_limit → 0건).
갭"리셋 후 알아서 재시작"의 절반(감지·기록)만. 핵심 절반(정확한 시각 파싱·시각 도래 시 재개·가시화) 전부 미연결. 부팅 복구도 dispatched/running만 재큐, rate_limited는 손대지 않음.
증거host_daemon.py:93-99 · orchestrator.py:109 · scheduler_loop.py(resume 없음) · routers grep resume → 0 · web grep rate_limit → 0

MAJOR  5. 위키 Ingest가 Claude opus 합성이 아니라 단순 표시

D16 · §16 · §9 E2E "ingest(Claude opus) 합성"
기획"Ingest(02:00): maintainer = Claude 고정(opus + 최대 effort)가 규약대로 raw→wiki 합성" → outcome·스킬후보 추출 → RAG 재임베딩.
구현scheduler_loop.ingest()는 pending WikiSyncJob을 ingested로 표시하고 raw 파일 목록 _index.md만 작성. LLM(opus) 합성 호출 없음. 현재 존재하는 wiki 합성 페이지는 시스템 ingest가 아니라 외부/수작업 산출.
갭자기진화 루프의 "ingest 합성" 단계가 사실상 no-op → outcome 태깅·반복패턴 concept화·스킬후보 자동 도출(§16.1) 모두 출발점 없음.
증거scheduler_loop.py ingest() (파일 인덱싱만, LLM 호출 없음)

MAJOR  6. 실제 Executor(tmux 인터랙티브)가 기본 실행 스택 밖

D3 · §10 · §23 성공기준
기획"Executor = 전용 tmux 새 윈도우의 인터랙티브 CLI(print/exec 아님)". Host 데몬이 큐 폴링→실행, Watcher가 윈도우 감시→완료 시 kill.
구현host_daemon.py+cli_exec.py가 tmux new-window 인터랙티브 설계를 구현(좋음). 그러나 이건 호스트에서 real 모드로 수동 실행해야 하고 compose 스택에 없음. 컨테이너 기본 실행기는 worker_loop→adapter = simulated 산출물 또는 subprocess.Popen(비인터랙티브).
갭기본으로 돌아가는 시스템은 tmux 인터랙티브 CLI가 아님 → "권한 프롬프트 없이 인터랙티브 실행·완료 시 윈도우 kill" 성공기준이 기본 경로에서 미충족. 추가로 send-keys "$(cat prompt)"는 멀티라인 프롬프트에 취약, 완료 판정 휴리스틱도 "튜닝 필요"로 자인.
증거adapter.py:77-122(Popen/simulated) · host_daemon.py(compose 미포함) · cli_exec.send_prompt_command

MINOR  8. RAG가 pgvector·실임베딩이 아니라 해시 BoW

MINOR  10. 권한: 설정파일 기록·scope·settings_path 없음

D9 · §11 · §20
기획"UI→API가 settings.json/config.toml로 기록→데몬이 그 설정으로 시작". 권한 scope = 보드/프로젝트/에이전트 단위. 모델 필드 scope·mode·settings_path·allow/deny.
구현플래그 조립은 정확(permissions.flags_for)하고 데몬이 argv로 전달. 그러나 settings.json/config.toml에 기록하는 코드 없음(allow/deny 저장돼도 파일 미반영). 프로필은 brain 단위 전역만(scope·settings_path 컬럼 없음, mode 대신 preset).
갭보드/프로젝트별 권한 스코프 불가, allow/deny가 실제 CLI 설정에 적용 안 됨(플래그 모드만 적용).

MINOR  11. 데이터 모델 잔여 차이
